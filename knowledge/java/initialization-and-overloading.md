# Java 类初始化、对象构造与方法重载

## Java 中父子类的静态代码块、构造代码块和构造方法的执行顺序是什么？为什么子类要先执行父类的构造方法？

创建子类对象时，先执行父类静态代码块，再执行子类静态代码块（静态代码块在类初始化时执行一次）；随后执行父类构造代码块、父类构造方法、子类构造代码块、子类构造方法。子类构造方法默认通过 super() 调用父类无参构造方法，因此必须先完成父类的构造过程。若父类没有无参构造方法，则需要显式调用可用的父类有参构造方法。

## Java 方法重载的判断条件是什么？返回值类型和访问修饰符不同，可以构成方法重载吗？

方法重载要求方法名相同、参数列表不同，通常发生在同一个类中，父类和子类之间也可能存在重载。参数列表不同包括参数类型、个数或顺序不同。返回值类型和访问修饰符可以不同，但不能单独作为构成方法重载的条件。即使返回值和访问修饰符都不同，只要参数列表相同，也不能构成重载。

## 构造顺序的条件与版本差异

上面的顺序适用于传统写法：例如 Java 21 中子类构造器先调用父类构造器，再执行子类初始化器和剩余构造器体。父类先建立其负责的状态，子类才能在这个基础上继续初始化。实例字段初始化器与实例代码块按源码出现顺序执行；每次创建实例都会执行。静态字段初始化器与静态代码块也按源码顺序执行，但只在该类初始化时执行一次；若父类已初始化，不会再次执行父类静态块。

Java 25 的灵活构造器体允许在显式 super(...) 或 this(...) 前执行受限制的语句，因此不能概括为“子类构造器的任何代码都晚于父类”。父类构造返回后，仍执行子类实例初始化器及构造器后半段。若构造器通过 this(...) 委托，最终沿构造链调用父类构造；同一对象的本类实例初始化器不会因委托而重复执行。隐式 super() 要求父类无参构造器可访问；显式有参调用也须满足访问权限。

重载在编译期根据参数等规则选择；与运行期按实际对象选择覆盖方法不同。例：void print(int n) 与 void print(String s) 构成重载；仅把 int value() 改成 String value() 不能在同一类中形成另一重载。继承中还要满足可访问性、覆盖、类型擦除等规则，不能只凭返回类型不同判定合法。
