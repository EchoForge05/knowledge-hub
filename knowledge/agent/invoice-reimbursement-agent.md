# 用 Java 与 Spring AI 设计智能报销 Agent

报销系统要完成两类工作。一类是读懂员工的需求、从发票提取字段、找到适用的制度并解释结果。另一类是核验发票、计算金额、检查重复报销并推进审批。前一类可以交给 OCR、模型和检索工具协作，后一类继续由 Java 业务服务按权限和生效规则执行。本文的金额、规则和工具名均为设计示例。

## 什么情况下才需要 Agent？

如果流程始终是上传发票、OCR 识别、自动分类、Java 校验、提交审批，固定工作流就够用。即使分类环节使用模型，流程仍由工作流控制，OCR 和 RAG 也都只是其中的能力。

当员工提出「帮我审核这张发票，超标的话查一下例外政策」时，路径会随情况变化。Agent 可以根据字段缺失、校验结果和用户目标，选择查询员工信息、检索条款、追问证明材料或申请重新校验。Java 服务和工作流负责限定可调用工具、可执行状态迁移和需要人工确认的步骤。

## 一张 800 元的住宿发票怎么处理？

1. **提取并确认字段。** 调用 OCR 或视觉模型提取金额、日期、号码和开票单位，再判断是住宿、交通还是餐饮。金额等字段置信度低时，请员工确认。识别成功只表示读出了内容，发票真实性仍需业务服务核验。
2. **查员工和适用制度。** 用 `getEmployeeInfo(employeeId)` 获取部门和职级等必要信息，员工身份及可访问范围由服务端根据登录态校验。通过 RAG（检索增强生成）找相关制度。例如当前员工在示例场景下的住宿标准为每天 500 元。
3. **执行确定性校验。** 调用 `validateReimbursement(employeeId, invoiceInfo)`。Java 以有效规则配置、身份、住宿天数及已确认字段为准，检查重复报销并返回结构化结果。住宿一天时，发票金额 800 元、标准 500 元、超标 300 元，状态为需进一步审核。
4. **处理例外。** 查找适用的例外条款及证明要求，提示员工补交材料，再交 Java 复核。特殊审批进入审批工作流。缺少适用条款或信息时，保留待确认状态。
5. **解释并提交。** Agent 可以说「这次住宿费为 800 元，当前适用上限为 500 元，超出 300 元。请补充特殊情况说明，供后续审批。」正式提交、审批或资金操作按权限和业务状态执行，并在规定环节取得确认。

Java 继续负责发票核验、规则校验、金额计算、审批状态、持久化、事务和审计。提交接口可以用稳定的申请标识做幂等校验。工具超时或响应丢失时先查询已有处理状态，避免再次提交。日志记录工具操作、规则版本和审批结果，按权限保护发票及员工资料。

## 制度从 500 元改成 600 元，系统怎么跟进？

把供人阅读的制度文档和供 Java 执行的结构化规则分开管理，发布时对齐它们的版本和生效时间。

- **制度文档**可用 PDF、Word 或 Markdown。选择适合来源格式的读取器，经过文本切分、Embedding 和向量存储建立索引。检索按可见范围、适用版本和日期过滤，回答可以附上引用条款。制度更新后重新索引受影响的文档，并按版本保留必要的历史条款。
- **执行规则**把费用类型、员工职级和上限维护在数据库或规则配置中。审批通过后发布有效版本，Java 按业务定义的适用日期读取 500 元或 600 元规则，无需为单纯的配置变更改代码。审核记录关联实际使用的版本，避免历史申请在制度变更后被重新解释。
- **发布验证**覆盖生效日前后、历史记录、超标和例外审批。检索内容与执行规则发生差异时，展示实际校验使用的版本并转复核。

## Prompt、Tool 和 Skill 各管什么？

| 概念 | 在报销场景中的作用 |
| --- | --- |
| Prompt | 表达当前任务和约束，例如审核发票、查询条款并解释结果 |
| Tool | 提供识别、员工查询、规则校验、制度检索或审批申请等外部能力 |
| Skill | 组织可复用的处理方法，例如字段检查、例外分支、异常处理和报告结构 |

Spring AI Tool Calling 可以把 Java 能力注册为工具，提供名称、描述和参数 Schema。模型发出调用请求，应用执行并回填结果。Skill 可以按任务加载，为工具选择提供步骤和规则。真正的参数校验、授权与状态校验仍在服务端执行。发票识别文本和检索条款都作为数据处理，其中的文字无权扩大工具权限。更多消息和工具上下文细节见 [Agent 的 Prompt 与 Context](prompt-and-context.md)。

## 面试时怎么把架构讲完整？

我会保留原来的 Java 报销服务，让模型理解员工的自然语言需求，并用 OCR 或视觉模型填发票字段。常规报销走固定工作流。遇到超标、缺材料或需要多轮查询的场景，Agent 才在授权范围内动态选工具。RAG 提供可追溯的制度依据，Java 根据有效规则算金额、判状态、写记录。制度文档与规则配置按版本和生效日期一起发布，提交和审批通过权限、人工确认、幂等和审计来控制。实现时重点验证工具描述和参数 Schema、检索和索引更新、多轮状态、Spring Boot 服务异常处理以及重试边界。
