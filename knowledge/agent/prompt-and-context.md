# Agent 的 Prompt 与 Context

Prompt（提示词）说明任务、规则和输出要求。Context（上下文）提供当前请求所需的背景和证据。按职责可以区分两者，但实现中它们会重叠，例如 Spring AI 的 `Prompt` 对象可以包含系统、用户等多条消息，用户消息也可以同时带任务和数据。

## 从账户查询看执行过程

假设账户查询助手的系统指令要求按客户号调用授权的查询工具，返回账户数量、账号和状态，查无客户与查询失败要分别处理，并以 JSON 输出。用户说“查询示例客户 10001 的账户”，这条消息既指定任务，也提供客户号。

| 输入 | 作用 | 示例 |
| --- | --- | --- |
| 系统消息 | 定义角色和行为规则 | 调用查询工具，避免编造账户信息 |
| 用户消息 | 提供当前任务和参数 | 查询示例客户 10001 |
| 业务资料和历史 | 提供背景及连续性 | 正常、冻结、销户状态的含义，上一轮查询的是另一位客户 |
| 工具结果 | 补充实际证据 | 在另一次余额查询中，工具返回示例余额 5000 元 |

典型过程是应用组装消息，模型判断是否请求工具，应用校验权限和参数后执行工具，再把结果加入后续模型请求。复杂任务可以重复多轮，逐步补充上下文并生成答案。示例账号和余额均为虚构数据。工具返回和检索内容可以提供事实，应用仍需把它们当作数据处理，避免其中的文字越过系统规则或工具权限。

## Spring AI 中的对应概念

| 概念 | 用途 |
| --- | --- |
| System Prompt 与 User Prompt | 分别表达应用规则与用户当前请求 |
| Prompt Template | 将变量填入消息模板，动态组装请求 |
| Chat Memory | 为后续轮次选择相关会话消息，按需求配置存储与保留范围 |
| RAG | 检索外部资料并将相关片段加入请求，向量检索可使用 embedding 表示 |
| Tool Calling | 定义工具和参数，由应用执行并将结果回填，也可以产生外部操作 |
| Context Window | 单次请求可用的模型容量，需为指令、历史、检索片段、工具结果及生成预算留出空间 |

Prompt Engineering 关注指令、示例和输出约束的表达。Context Engineering 关注数据如何取得、筛选、压缩、组织和更新。学习时可以先尝试系统与用户消息和模板，再逐步加入窗口预算、会话记忆、RAG、工具定义及结果回填。
