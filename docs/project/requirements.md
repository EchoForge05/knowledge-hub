# 需求基线

记录日期：2026-10-31（Asia/Shanghai）。来源：用户本会话的完整项目需求及末尾的当前执行范围。此文件为结构化摘要；出现遗漏或歧义时回到用户原意确认，不能自行扩大范围。

## 三个长期目标

1. 随时通过电脑、手机网页浏览、搜索和阅读知识。
2. 随时向 Agent 提交零散记录，由 Agent 维护持续演进的知识体系。
3. 代码和知识通过 GitHub 长期保存、版本管理，方便持续扩展。

## 当前明确授权的范围

- 检查空目录和环境，创建本地 Git 仓库。
- 建立基础目录、重要文档、Agent 规则和规划记录机制。
- 分析可优化之处，提出供下一轮讨论的方案。
- 当前优先调通 Git；已确认使用 HTTPS 连接公开仓库 `EchoForge05/knowledge-hub`。Git 配置缺失项向用户询问；不猜测身份或凭据。
- 用户先要求规划完整前不提交，后续已明确授权本轮对话落盘后创建一次本地提交；不推送，不在远程自动创建 README 提交。
- 目前不进行网站、脚本、自动化或 AI 集成开发，不部署。与上一轮相比，Git/GitHub 配置和连接验证已进入当前范围。
- 本轮之后先完善需求，再确认开发计划，分阶段完成并验证。草案计划不构成开工授权。

## 本轮新增确认

- 选择免费的公开方案；当前个人知识不涉及隐私，站点无需登录访问。
- 先做 MVP；先验证网页阅读搜索与直接输入知识维护，Issues 后续增加。具体 MVP 范围草案见 roadmap.md。
- 同意将更新、去重、矛盾保留纳入验收；中文搜索需包含中文短语、缩写、类名及 SQL。
- 同意由 Agent 整理、检查并提出 PR，用户审核合并。
- 框架继续讨论：用户有 Java 基础，同时愿意选择更适合本项目的技术，不要求 Java 实现网站。
