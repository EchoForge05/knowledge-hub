## MVP 范围（D021 按计划执行）

- 一个使用默认主题的公开静态知识站：分类导航、全文搜索、Markdown/代码/表格/图片/内部链接、电脑和手机阅读。
- Codex 直接输入的最小维护闭环：检索、新建或更新、去重、标记疑点与保留来源，用同一主题样本验证新建/补充/重复三种输入。
- 必要的文档/链接/构建检查，以及知识修改 PR 审核和合并后 Pages 部署。真实外部运行通过后才计入完成。
- 简明的使用说明和项目续接记录，不增加独立后台、数据库或定制主题。
- Issues AI 录入、RAG、语义搜索、复杂自动分类服务、多 Agent 编排不进入 MVP。

按已采纳规划，先让网页阅读搜索可用，再补知识维护样本和持续交付；P2–P4 是可逐项验证的 MVP 切片，不要求一次性全部开发。项目重点是知识站；P3 为配套维护试点，不扩展成独立 Agent 平台。下文给出具体任务提案，真实样本与必要调整在进入对应阶段前确认。

## 风险与调整边界

- 搜索不达标：先定位索引与配置，再评估最小分词调整；新增依赖或更换服务前记录依据、维护成本和影响，不能跳过失败验收。
- 样本后续需持续扩充；目前 6 篇官方资料摘要已落实，不能用演示文章冒充真实知识。
- 导航维护增加：先保持少量明确配置；仅当真实维护出现重复负担时考虑生成工具，避免提前开发框架。
- 认证或外部运行受阻：保留本地成果、记录具体未验证项，不将 P4 归档为完成。
- 需求扩大：定制主题、后台、登录、RAG 与多渠道输入另提计划，不挤入当前 MVP。
