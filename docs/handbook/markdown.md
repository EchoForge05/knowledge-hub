# Markdown 文档规范

当前适用于规划文档和后续知识正文；VitePress 已选定，框架特有语法的使用范围在开发验证后确定。

- 使用 UTF-8、LF；每篇一个一级标题，标题准确表达主题，标题层级连续。
- 正文以中文为主，保留英文术语和代码原名；路径采用简洁小写英文与连字符，减少重命名造成断链。
- 一个文档维护一个连贯主题，不按每次输入生成新文档；不设机械字数阈值，出现多个独立主题时考虑拆分。
- 技术结论注明必要的环境、版本与前提。区分事实、经验、推测和待核实；不将建议写为普遍规律。按D040的[阅读精简规范](development.md#知识文章的阅读精简)先给结论与必要操作，补充资料可用原生`<details>`/`<summary>`折叠；影响结论的条件、风险与待核实事项必须就近明示。
- 代码块填写语言；保留重要上下文，用占位符替换敏感参数，不把伪代码描述为已运行示例。
- 表格带表头，单元格避免长段落；代码和表格的移动阅读效果由网站阶段验证。
- 内部链接优先使用相对路径，移动文件时检查所有引用；外部链接给出说明文字。
- 图片放 `knowledge/assets/images/`，使用有意义的文件名与替代文本，确认授权并检查截图中的敏感信息。
- 知识正文按需包含“适用环境”“相关知识”“来源”“待核实”；不要求空模板段落，不先引入复杂 frontmatter。
- 正文保留可独立核查的公开来源，会随时间变化的结论记录核查日期；输入编号/摘录、公开范围等维护溯源留项目记录，只有没有公开外链的原创输入才按需在正文保留简短溯源，不堆叠过程信息。
- 待核实内容要写清疑点和如何验证；文档拆分或去重不得删除有价值的原始细节和证据。

提交前人工检查标题、代码围栏、表格、链接、来源、敏感数据和重复内容；自动校验规则将随对应阶段逐步实现。
