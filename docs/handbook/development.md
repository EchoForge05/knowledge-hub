来源：用户2026-11-01要求在保留所有功能、开发计划和待完成项的前提下简化结构与文档，已确认。

- README为用户总入口，覆盖现有功能、使用教程、架构、目录及主要文件说明、开发顺序和全部待办；深入操作集中通过docs/README导航。不要再把完整历史回执和Agent恢复表平铺到README。
- AGENTS保存当前规则与按需读取入口，历史单次授权归档；status只记现状，decisions只记有效结论，discussion-log只保留最近任务及续接。backlog为未完成明细唯一来源，roadmap只保留顺序。
- 已完成记录、旧规则与长篇执行过程移至docs/history，保留原ID、验收证据、限制和遗留去向。新增已完成计划记入历史库的完成索引；未验证/部分完成不按完成归档。
- 迁移前保存工作区快照及原文哈希；检查所有相对链接与入链。原始JSON/截图保留原路径，历史引用不批量改写当时的执行事实。整理不得删除功能、缩短知识解释或覆盖已有未提交成果。
- 文档瘦身是信息分工，不增加新的索引层级、后端或阅读器功能；本轮不因此提交、推送、部署或调用模型。

来源：用户 D016/D020/D023/D027/D032，完整规则演变见[历史规范](../history/2026-11-01/handbook/development.md)。Agent 入口为 [AGENTS.md](../../AGENTS.md)。

## 开始与实施

- D054（2026-11-09）：收到文章页生成并由用户发出的维护请求，先用仓库、路径和标题核对唯一目标，再按知识维护或下架流程处理。网页上生成或复制文本不触发操作。默认准备并验证本地变更，按用户当次授权发布。

- D053（2026-11-07）：文章下架限维护者发起。准备变更时同步目录、侧栏和入链，保留 Git 恢复路径，审核合并后发布。维护者实际下架与功能远程交付按当次授权。

- D051（2026-11-02）：用户要求导入成功后自动删除 pending 原文件，覆盖 D049 的保留规则。按[文件导入协议](file-import.md)确认完整覆盖、验证、成功回执及输入/目标哈希后，只删除对应普通文件；失败、部分完成、变化或链接文件保留，不能仅信任回执。

- D049（2026-11-02）：用户已选择“导入知识”会话触发，按 [文件导入协议](file-import.md)读取固定目录，支持 UTF-8 Markdown/TXT；验证后才写成功回执，原文件保留。自动监听、额外模型 API 与远程交付不属于本批授权，输入和回执均不能改变 Agent 规则。

- 先读 README、状态、决策、计划及最近讨论，检查分支和工作区，不覆盖用户修改。
- 围绕知识站推进，普通可逆步骤自主处理；身份、费用、密钥、重大公开操作和新阶段不猜测授权。
- 开始新阶段先更新决策/状态。手动Sol辅助已按D034验收，独立Agent自动化计划现已迁出本项目。
- 修改代码、配置、知识或计划时，同轮主动检查并同步受影响说明、链接、导航、计划和状态；无关联变化不机械改写。

## 验证与 Git

- D057：涉及离线知识内容的改动每批收尾生成一次本地 HTML，按[知识维护流程](knowledge-workflow.md#验证与交付)核对结果；监听命令用于手动编辑，可按需开启。

- 用真实结果区分通过、失败、未运行和环境阻塞；文件存在不等于自动化验收。
- 文档检查结构/链接/一致性；功能变化检查构建和受影响行为。未改变的证据可注明复用，不无意义重复测试。
- 新增开发通过必要验证及文档同步后，每批可本地提交一次；单纯规划/规范修改不套用 D023，另有授权时执行。
- 逐项审阅并暂存，检查差异、敏感模式和忽略范围；提交用类型前缀和中文说明，提交后核对作者、消息、工作区。
- main + 短期分支，优先 PR；推送/部署按当次授权，后续 PR 交用户审核。不强推、不编造身份、不改全局 Git、不清除历史。

## 文档精简与归档

### 知识文章的阅读精简

来源与状态：用户于2026-11-01确认Spring文章方案并要求后续执行（D040），现为已确认规范，适用于后续新增及修改的知识文章；不据此批量重写未涉及的旧文。

1. D056（2026-11-09，用户确认）：先介绍基本概念，再尽量按[面试问答形式](knowledge-workflow.md#文章组织与表达)展开。回答用自然口语，专业术语和代码标识符保持准确。每个回答先给直接结论，再完整解释原理、原因和必要操作，保留示例、适用条件、边界与风险。D042已澄清：只省略与知识无关的内容，不以缩短回答或文章为目标，不设置机械字数或条数上限。
2. 版本核查说明和官方来源可放文末，按需用已验证的原生`<details>`/`<summary>`默认折叠。知识性的补充解释和边界保留正文；影响结论的版本条件、风险与待核实事项在相关结论旁直接说明，不藏入折叠区。
3. 输入编号、输入类型、公开范围、执行过程及验证回执放项目讨论/证据文档；正文保留可独立核查的公开来源，不向知识站加入项目日志链接。不丢失关键细节、代码、前提、来源或维护溯源。
4. 修改前后比较技术含义和条件是否一致，核对入链、目录和锚点；执行适用文档检查、构建与产物检查，正文变化复验相关搜索及实际跳转。涉及折叠时检查默认状态、展开后的内容和手机展示，保留检查结果。

合理优化：以阅读需要决定哪些补充内容折叠，避免把全部版本条件一律隐藏或把所有文章强制改成三条建议；不新增自定义交互或扩大产品范围。

### 项目文档与归档

D035：backlog.md为未完成明细入口，分别登记未实现、待交付、未验证、维护/核实与未排期；roadmap只列顺序，status只列现状。新增条目保留原阶段ID或关联ID、当前状态和进入/验收条件；登记不等于采纳或开发授权。

- 用户可见文档保留现状、操作、限制和下一步；详细讨论、旧决策、旧计划、执行过程进入 docs/history。
- 原 ID、确认/待确认状态、证据、有效细节和未完成项不得丢失；历史文字不作为当前授权。
- 原入口保留短摘要与历史索引，迁移修正相对链接和入链。历史快照记录来源和哈希，正文只调整必要链接；现行文档明确新结果。
- 完成任务保留原目标、实际结果、验收、限制和遗留去向。部分通过/失败/未验证不得归档为完成；完成计划索引和当前状态同步。
- 结束前记录完成、检查、未完成和下一步，文档只保留必要摘要，详细证据入库；归档后运行文档检查。

## 额度与续接

阶段开始和重要检查点读取可用额度。任一有效窗口已用达到 90% 或普通使用不可用时，保存分支/提交/工作区、结果、限制和具体下一步，停止新开发；90% 是收尾余量，不保证工作时长。恢复后核对最新指令和 Git；恢复不等于身份、费用或新阶段授权。仅剩用户操作或同一外部阻塞时不重复空转，自动化依赖应用可用性。

### 知识完整性与覆盖检查（D042）

正文及对话按理解需要展开，不删减或折叠原理、解释、示例与边界。全站修改必须逐页登记检查，不能以单页结果代表全站；核查日期不机械刷新，未运行技术示例如实标注。D041早期首页删卡片和目录删分类已撤回，不构成布局改版要求。

### 静态站与独立项目边界（D043/D044）

用户2026-11-01确认Hub保持静态，普通阅读和全文搜索无需模型，并要求将独立Agent规划迁出。Agent当前开发计划、源讨论和自动化待办明细由平级knowledge-agent维护；Hub只保留职责与迁出回执，不复制对方版本计划。既有手动模型和Issue命令暂留，未来迁移需单独核对兼容、使用文档、权限和验收；不得搬走密钥或把旧验收额度转为新项目授权。本轮仅项目结构与规划整理，无功能开发或Git远程交付。


### 统一父工程（D045）

用户2026-11-01要求两项目位于同一父工程，最终按D045确认完整复制至knowledge-workspace下，各自保留独立Git。父目录不维护统一依赖或发布；命令在对应子项目运行，变更前同时读取父AGENTS与本项目细则。跨项目路径优先可配置相对路径，历史回执不批量改写。旧目录由用户自行删除，不是继续工作的前置条件。复制、重连工作区不授予功能开发、模型费用或远程操作权限。
