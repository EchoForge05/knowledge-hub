# 开发约定

来源：用户 D016/D020/D023/D027/D032，完整规则演变见[历史规范](../history/2026-11-01/handbook/development.md)。Agent 入口为 [AGENTS.md](../../AGENTS.md)。

## 开始与实施

D033：主维护方式保持 Codex 直接输入；GreatRouter API 是可选辅助，不将可用密钥、付费余额或外部模型作为阅读/构建/发布的必需条件。用户已限定为编程技术资料、低频且质量优先；未给出数值预算。本地实现/离线测试可先行，真实调用仍须核对模型、价格和允许发送的资料，不将价格页或宣传当作无限调用授权。

- 先读 README、状态、决策、计划及最近讨论，检查分支和工作区，不覆盖用户修改。
- 围绕知识站推进，普通可逆步骤自主处理；身份、费用、密钥、重大公开操作和新阶段不猜测授权。
- 开始新阶段先更新决策/状态。P5 服务、费用和外发范围仍待确认。
- 修改代码、配置、知识或计划时，同轮主动检查并同步受影响说明、链接、导航、计划和状态；无关联变化不机械改写。

## 验证与 Git

- 用真实结果区分通过、失败、未运行和环境阻塞；文件存在不等于自动化验收。
- 文档检查结构/链接/一致性；功能变化检查构建和受影响行为。未改变的证据可注明复用，不无意义重复测试。
- 新增开发通过必要验证及文档同步后，每批可本地提交一次；单纯规划/规范修改不套用 D023，另有授权时执行。
- 逐项审阅并暂存，检查差异、敏感模式和忽略范围；提交用类型前缀和中文说明，提交后核对作者、消息、工作区。
- main + 短期分支，优先 PR；推送/部署按当次授权，后续 PR 交用户审核。不强推、不编造身份、不改全局 Git、不清除历史。

## 文档精简与归档

- 用户可见文档保留现状、操作、限制和下一步；详细讨论、旧决策、旧计划、执行过程进入 docs/history。
- 原 ID、确认/待确认状态、证据、有效细节和未完成项不得丢失；历史文字不作为当前授权。
- 原入口保留短摘要与历史索引，迁移修正相对链接和入链。历史快照记录来源和哈希，正文只调整必要链接；现行文档明确新结果。
- 完成任务保留原目标、实际结果、验收、限制和遗留去向。部分通过/失败/未验证不得归档为完成；完成计划索引和当前状态同步。
- 结束前记录完成、检查、未完成和下一步，文档只保留必要摘要，详细证据入库；归档后运行文档检查。

## 额度与续接

阶段开始和重要检查点读取可用额度。任一有效窗口已用达到 90% 或普通使用不可用时，保存分支/提交/工作区、结果、限制和具体下一步，停止新开发；90% 是收尾余量，不保证工作时长。恢复后核对最新指令和 Git；恢复不等于身份、费用或新阶段授权。仅剩用户操作或同一外部阻塞时不重复空转，自动化依赖应用可用性。
