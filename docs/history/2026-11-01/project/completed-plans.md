按 P3-01 → P3-02 → P3-03 → P3-04 执行，不并行修改同一主题。具体安排：

1. **新建：** 读取编号输入、检索标题/别名/正文，确认独立主题后新增文章；同步知识目录、侧栏和必要关联链接。保存新建前后快照与判断依据。
2. **增补：** 向同一主题加入一条有来源的新信息，更新原文并保留有效旧细节；保存补充前后差异，不能仅用最终文章证明发生过增补。
3. **重复：** 分别重放完全相同输入和语义近似输入。比较 knowledge/ 与导航配置的前后文件清单及内容哈希，预期均无变化；项目证据日志可增加记录，但不得在知识正文追加“已处理”等无意义内容。
4. **矛盾与不确定性：** 分开测试可核实矛盾和缺少依据的说法。前者比较环境/版本及官方依据后解释取舍；后者保留可公开原意、疑点和验证方法，标为待核实。不把人工错误命题当成已确认知识写入正文；需要保留的测试原意可存于证据区并关联主题。
5. **固化维护方法：** 基于实际试点完善 knowledge-workflow.md、必要的输入说明和站点维护指南；沿用现有检查脚本，只有发现真实缺口才补最小检查，不引入模型 API 或通用测试平台。
