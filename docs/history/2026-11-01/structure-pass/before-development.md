## 验证与 Git

## 文档精简与归档

### 知识文章的阅读精简

来源与状态：用户于2026-11-01确认Spring文章方案并要求后续执行（D040），现为已确认规范，适用于后续新增及修改的知识文章；不据此批量重写未涉及的旧文。

1. 先给直接结论，再完整解释原理、原因和必要操作，保留示例、适用条件、边界与风险。D042已澄清：只省略与知识无关的内容，不以缩短回答或文章为目标，不设置机械字数或条数上限。
2. 版本核查说明和官方来源可放文末，按需用已验证的原生`<details>`/`<summary>`默认折叠。知识性的补充解释和边界保留正文；影响结论的版本条件、风险与待核实事项在相关结论旁直接说明，不藏入折叠区。
3. 输入编号、输入类型、公开范围、执行过程及验证回执放项目讨论/证据文档；正文保留可独立核查的公开来源，不向知识站加入项目日志链接。不丢失关键细节、代码、前提、来源或维护溯源。
4. 修改前后比较技术含义和条件是否一致，核对入链、目录和锚点；执行适用文档检查、构建与产物检查，正文变化复验相关搜索及实际跳转。涉及折叠时检查默认状态、展开后的内容和手机展示，保留检查结果。

合理优化：以阅读需要决定哪些补充内容折叠，避免把全部版本条件一律隐藏或把所有文章强制改成三条建议；不新增自定义交互或扩大产品范围。

### 项目文档与归档

D035：backlog.md为未完成明细入口，分别登记未实现、待交付、未验证、维护/核实与未排期；roadmap只列顺序，status只列现状。新增条目保留原阶段ID或关联ID、当前状态和进入/验收条件；登记不等于采纳或开发授权。

- 用户可见文档保留现状、操作、限制和下一步；详细讨论、旧决策、旧计划、执行过程进入 docs/history。
- 原 ID、确认/待确认状态、证据、有效细节和未完成项不得丢失；历史文字不作为当前授权。
- 原入口保留短摘要与历史索引，迁移修正相对链接和入链。历史快照记录来源和哈希，正文只调整必要链接；现行文档明确新结果。
- 完成任务保留原目标、实际结果、验收、限制和遗留去向。部分通过/失败/未验证不得归档为完成；完成计划索引和当前状态同步。
- 结束前记录完成、检查、未完成和下一步，文档只保留必要摘要，详细证据入库；归档后运行文档检查。

## 额度与续接

阶段开始和重要检查点读取可用额度。任一有效窗口已用达到 90% 或普通使用不可用时，保存分支/提交/工作区、结果、限制和具体下一步，停止新开发；90% 是收尾余量，不保证工作时长。恢复后核对最新指令和 Git；恢复不等于身份、费用或新阶段授权。仅剩用户操作或同一外部阻塞时不重复空转，自动化依赖应用可用性。
